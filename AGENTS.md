# AGENTS.md

Notes for AI agents working on open-scansnap. Keep project knowledge here, not in agent memory. The README covers install and use, `docs/DEVELOPMENT.md` building and the command line; this file covers what the code cannot tell you.

## Goal and owner rules

Replace ScanSnap Home for a ScanSnap iX500 on Wi-Fi: a PDF in `~/Downloads` that looks like ScanSnap's "Document" output (cropped, deskewed, upright, blank sides dropped, black and white for text pages, searchable). The owner wants it "as good as ScanSnap software or better".

- **Use existing software.** Research before building.
- **No custom image processing.** A hand-written OpenCV crop/flatten/levels pipeline was rejected.
- **No settings tuned on one sheet.** Each page's treatment must come from that page: established algorithms, objective scores (Tesseract), or boundaries with a stated physical or published basis. No LLMs.
- Work through `/principal:code`.
- **No firmware updates.** They stay with ScanSnap Home: a failed or wrong update can leave the scanner unusable, and none can be tested safely (owner, 2026-11-22). `firmware.NEWEST` holds the newest firmware per model, from PFU's firmware page.
- **Anything that changes the scanner's settings** (Wi-Fi network, the computers allowed on Wi-Fi) is sent only by an explicit user action in the app, after the user sees what it changes.
- **License: MIT** for open-scansnap's own code. Push it with fresh history: the upstream clone's commits (Bram Heerink, Axel Lodyga) are GPL-2.0. Its code is gone; only protocol facts, which are not copyrightable, were kept. Do not add GPL code to this repository. SANE stays GPL (our `fujitsu.c` changes must); its linking exception lets MIT code call it. Avoid Ghostscript (AGPL): `pypdfium2` rasterizes for OCRmyPDF. A bundled app must carry every component's license and point to the SANE fork's source; img2pdf (LGPL-3.0) must stay replaceable, so bundle it as plain `.py` files.

## Layout

- `sane-backends/`: clone of https://gitlab.com/sane-project/backends, branch `vens`, not yet published or committed. It holds the Wi-Fi transport in the `fujitsu` backend: `backend/fujitsu-vens.{c,h}` (packets), Wi-Fi command definitions at the end of `backend/fujitsu-scsi.h`, the `vens_*` functions and hooks in `backend/fujitsu.c`, docs in `doc/sane-fujitsu.man` and `doc/descriptions/fujitsu.desc`. Users configure `wifi HOST` with `option wifi-hostid` and `option wifi-password`; device names are `fujitsu:wifi:HOST`. "VENS" (the packet magic) names only the internals. Built into `sane-prefix/` (see docs/DEVELOPMENT.md).
- `openscansnap/`:
  - scanning: `sane.py` (SANE configuration and `scanimage`), `saneapi.py` (libsane through ctypes, for the sensors; a class, as libsane has init and exit; `leptonica.py`, stateless, loads its library once with `functools.cache`), `monitor.py` (the thread that owns the scanner, and the PDF thread), `job.py` (a batch: scan, then make its PDF);
  - finding the scanner: `discovery.py` (UDP search, this Mac's HostID), `scanner.py` (set up, follow to a new address, password; its `CONFIGURING` lock);
  - images: `sheet.py` (crop and straighten), `showthrough.py`, `pages.py` (per-page decisions), `languages.py` (each page's language, when Automatic), `pdf.py` (img2pdf and OCRmyPDF), `leptonica.py` (its skew measure, through ctypes);
  - settings: `options.py` (the scan's choices), `config.py` with `defaults.toml`, `files.py` (whole-file replacement, private folders);
  - review: `review.py` (the latest scan kept, its PDF made again as chosen), `reviewwindow.py` (its window);
  - the app: `menubar.py`, `wifiwindow.py` (Wi-Fi setup over USB), `firmware.py` (the newest firmware per model), `appicon.py`, `updates.py` (Sparkle), `bundle.py`, `selftest.py`; `__main__.py` is the CLI.
- `packaging/macos/languages.txt`: the OCR languages bundled besides English (tessdata_fast at a pinned commit, SHA-256 per file; the build checks them). Owner's choice (2026-11-22): the languages of most scanned documents, bundled, rather than a language menu with English only.
- `tests/`: fakes stand in for the scanner through `monitor.Device`; window tests keep their windows invisible (alpha 0) and never activate the app: the test process runs no event loop, so a visible window shows the owner a spinning cursor (2026-11-23); they derive from `offscreen.Offscreen`, which fails a test that leaves a window visible, and menu tests stand a mock in for the review window; one `test_<module>.py` per module, `test_cli.py` for the CLI; `test_wifi.py` with `fake_ix500.py` (the scanner's Wi-Fi firmware on localhost, driven by the real `scanimage`; strict about READ order) also answers the search.

Development setup: an iX500 with firmware 0U00 (the newest) and a Silex Wi-Fi module. SANE config in `~/.config/open-scansnap/sane.d/`.

## Protocol facts (verified against the scanner, 2026-11-22)

Ports: 52217/udp registration and search, 53219/tcp reservation, 53218/tcp commands, 55265/tcp trigger port the host announces ("Scan button notice" in PFU's docs).

Reservation (128 bytes on 53219), as built by ScanSnap Home's `+[SsSvcPCWIFITelReserveScanner initCreateSendData:…]`, big-endian:

| Offset | Field |
|---|---|
| 0 | Length (128) |
| 4 | `"VENS"` |
| 8 | Command 0x11 |
| 16 | Client MAC |
| 32 | Interface version, u16 (6) |
| 34 | Timeout, u8 (30 s) |
| 36 | Reserve mode, u32 |
| 40 | Password-present flag, u32 |
| 44 | Client IPv4 |
| 48 | Trigger port, u32 |
| 52 | Pairing key |
| 100 | Year u16, month, day, hour, minute, second |
| 108 | HostID, u64 |
| 116 | Negated GMT offset in seconds, i32 |

- **Pairing key:** the scanner password through `codePFUCipher`: `"%03d" % (ord("pFusCANsNapFiPfu"[i]) + ord(ch) + 11)` per character. Default password: last 4 characters of the serial.
- **HostID:** must be the one ScanSnap Home paired with. ScanSnap Home computes it as the Mac's MAC shifted left 16 bits, from interface en1 (else the first other `en1*`, else en0) (`_getHostId` in `SshResident`; verified: the value computed from the development Mac's en1 equals the plist's). It caches it in `~/Library/Preferences/com.fujitsu.pfu.ScanSnapHomeSetting.plist` (`Common` → `Wifi Connected Scanner` → `AutoConnectInfo_ScannerInfo` → `HostID`). `scanner.this_hostid` takes the plist's, else computes it.
- **Search** (verified 2026-11-22): ScanSnap Home's three 32-byte packets (`VENS`, `ssNR`, `V2ss`) to UDP 52217 at the broadcast address find every scanner. The scanner ignores a search without the client's IPv4 address at byte 8, but answers one without the client's MAC at 12, so `discovery` sends none (no identifier broadcast). Bytes 20–23 are the port to answer (ScanSnap Home binds 55264; any port works). The iX500's 132-byte reply: IPv4 at 0x10, ports at 0x14, scanner MAC at 0x1C, `model-serial` at 0x28, product at 0x68, a host IPv4 at 0x78 and HostID at 0x7C. Those two named the development Mac while the app was connected; whether they name the paired host when none is connected is not yet seen, so setup prefers a scanner naming this Mac's HostID but does not reject others. Nothing authenticates a reply; `discovery` keeps only replies from another host inside a searched network that name their sender's address and a `model-serial` name, and following searches only the configured scanner's network, where an answer from the configured address beats a look-alike.
- **Replies** (i32 at byte 8): 0 OK, -3 wrong key, -4 busy, -7 wrong HostID.
- **Reservations** are keyed to the client MAC; another MAC gets -4. **Keep-alive** (verified 2026-11-23): the scanner ends a reservation about 40 s after it began, whatever commands it gets, unless keep-alives arrive: the registration packet with u32 BE 1 at offset 4, to UDP 52217, as ScanSnap Home sends. The backend sends one at least every `VENS_KEEPALIVE_SECONDS` (10) from `do_vens_cmd`; sensor polling alone does not keep the reservation. **Release:** 32 bytes on 53219, command 0x12, MAC at 16; only the holder's release counts (`SsSvcPCWIFITelReleaseScanner`). The D6 command on 53218 ends the job, not the reservation.
- **Registration** replies are lost while the scanner's Wi-Fi wakes from sleep: send a round, wait, repeat.
- **53218 is a SCSI tunnel:** a 32-byte envelope (`len`, `"VENS"`, 1, 0, MAC, 10 zero bytes), `>IIII(cdb_len, read_len, write_len, 0)`, the CDB padded to 16 bytes, write data. Reply: 16-byte header with the SCSI status at bytes 12–15, 24 unused bytes, data.
- **The Wi-Fi firmware rejects** (sense 5/0x20) TEST UNIT READY, SET/GET WINDOW, SCAN, OBJECT POSITION, SEND, MODE SELECT/SENSE, SEND/READ DIAGNOSTIC, SCANNER CONTROL and ENDORSER. It accepts INQUIRY (and VPD 0xF0), REQUEST SENSE, GET HW STATUS, READ and ScanSnap Home's vendor commands. Their names, from `SsSvcPCWIFITel*` classes: d5 StartJob, d8 CancelRead, e9 SetPreReadMode, d4 SetParams (job settings and a window descriptor), e0 StartPaper, d6 EndJob, e6 PowerOffTime, e7 GetScannerInfo. A side is one READ (byte 3 = 0x02, window id 0x80 for the back, sequence number at byte 10, 12-byte CDB); it returns a 300 dpi color JPEG, then CHECK CONDITION with EOM/ILI. An empty feeder answers e0 with sense 3/0x80/0x03.
- macOS masks the MAC as `02:00:00:00:00:00` for programs using `getifaddrs` (so psutil too): the same value on every Mac. SystemConfiguration's `SCNetworkInterfaceGetHardwareAddressString` (and `ifconfig`) give the real one; `discovery.hardware_addresses` uses it for the HostID. The scanner accepts any client MAC, so the backend sends a locally administered MAC derived from the host UUID instead (`host_mac` in `fujitsu-vens.c`); otherwise two Macs would share one reservation.
- ScanSnap Home's helpers (`SshResident` and others) must be quit, or the scanner reports busy.

## Wi-Fi setup over USB (static analysis of ScanSnap Home's PfuSsWifiTool, 2026-11-22)

Verified on this iX500 over USB (2026-11-22): reading the allowed computers (`GET HOSTID LEN`/`GET HOSTID DATA`: one entry, this Mac), the network setup version (opcode 0xA: "02.02", so opcodes 6 and 7), the network it is set up for (opcode 7) and the networks it sees (opcode 6, signal in dBm). The session needs the scanner's Wi-Fi switch on: with it off, `SETUP NET START` answers 0x81. Not yet sent to the scanner: joining (0x1006), allowing a computer (`CLR`/`REG HOSTID`). The command layouts are in `fujitsu-scsi.h` (`NET_*`, `SD_wifi_*`) and the backend's `wifi_*` functions.

Two separate settings: the Wi-Fi network the scanner joins, and the computers allowed to scan over Wi-Fi (HostIDs). Phones (the ScanSnap iOS app) use the scanner's password, not that list. The app shows only the network; setting up Wi-Fi also adds this Mac to the list when it is not on it, as ScanSnap Home's setup does, and says so only when that removes another computer (owner, 2026-11-22). The scanner's WPS button joins a network without any app.

### Details

- On the iX500, pairing and Wi-Fi settings work over **USB only**: `PFUScannerIF scn_WifiConnectPC_Register:`, `scn_Wifi_Setting` and `scn_IP_Setting` do nothing over the network. They are SCSI SEND DIAGNOSTIC (`1D 00 00 LL LL 00`) with a 16-byte ASCII command, then RECEIVE DIAGNOSTIC RESULTS (`1C`).
- Pairing: `"CLR HOSTID ADATA"`, then `"REG HOSTID DATA "` + HostID (8 bytes, big-endian) + 8 zero bytes; reply byte 0 & 0x7f == 0 is success. PfuSsWifiTool (`CLR` then `REG`) and ScanSnap Home (`DoSetHostID:withDeviceHostID:`, delete-all then register) both clear the table first, so pairing evicts every other computer.
- Wi-Fi: a `"SETUP NET START "` … `"SETUP NET END   "` session of `"SETUP NET CMD   "` commands (opcode 0x1006 SSID and security, 0x1003 IP, 0x1002 name and password, 3 the access points it sees); the passphrase goes through the same cipher as the pairing key, with the iX500's table `aQweSrTywuIoppAsFdfGuhjkslZxCcvBAnmqNweRstyuNiopaAsdPfghajKlPzxc`.
- Over Wi-Fi, ScanSnap Home sends its HostID operation (tunnel CDB `DC`) only to model code 0x32, never to the iX500.
- Anything that changes the scanner's settings is sent only with the owner's go-ahead.

## How ScanSnap Home makes a "document"

All on the Mac, in `SsSvcImgFrmwk.framework` (bundles OpenCV and ONNX models); the scanner only scans in color. The "Document" profile sets Color Mode Auto, Mono Level 138, Blank Skip on. Steps: `PaperCrop`/`AutoSize`, `EraseEdgeShadow`, `DeskewImageWithIPP`, `DetectOrientation3`, `JudgeBlankPage`, `RemovalBleedThrough`, `IsColorMode`, `Gray2Mono`. Ghidra 12.2 (Homebrew formula `ghidra`, with OpenJDK 25) and REA (`npx rea-agents`, run with Homebrew's Node 26 because asdf pins Node 22.11) decompile `SsSvcPCWIFIFrmwk`.

## Design decisions

- **SANE does the scanner; `openscansnap.sheet` does the geometry.** The fujitsu backend already supports the iX500 over USB. Over Wi-Fi only the commands differ: `set_window`, `object_position`, `start_scan` and `read_from_scanner` branch to `vens_*` functions, and each decoded JPEG lands in `s->buffers[side]` in the packed-RGB layout the iX500's USB path produces, so everything downstream is unchanged. `vens_init_model()` switches off features whose commands are rejected; `has_cmd_scanner_ctl` matters most (otherwise every batch stalls 60 s retrying lamp-on).
- `check_status()` alone applies the busy/REQUEST SENSE/short-read rule for USB and Wi-Fi. Sense data may only shorten the received count: a scanner-supplied residual once wrapped the length and crashed `scanimage` (test: `test_bogus_residual_is_ignored`).
- A side is one READ that must hold a complete JPEG; `vens_decode` accepts only a baseline color JPEG within the scanner's area at the scan resolution, and treats libjpeg warnings (corrupt or missing data) as errors.
- Each `wifi` line becomes a `struct fujitsu_wifi_line` with the options in effect for it and its last attach status; `attach_one` gets the line, never the file-wide option globals. `sane_open` retries a failed line with that line's own options and returns the real status (busy, access denied) instead of "Invalid argument"; `openscansnap.sane` turns it into an instruction. Never attach a name the caller supplies: that would copy an unbounded string and send the stored password to whatever host the caller names.
- The transport's exported functions carry SANE's required `sanei_` prefix (`doc/backend-writing.txt`, `make libcheck`).
- A connection idle for 25–30 s is not trusted (measured before the keep-alive was known), so `vens_set_window` reconnects when the connection has been idle longer than `VENS_IDLE_MAX`. Cancelling over Wi-Fi ends the job (`OP_Halt`), since SCANNER CONTROL is rejected.
- `vens_init_model` also switches off the MODE SENSE and SEND DIAGNOSTIC probes at attach; `test_duplex_scan_uses_only_wifi_commands` asserts that the firmware rejects no command.
- The backend never logs the scanner's serial number or a config line's arguments: the serial's last 4 characters are the default password.
- Secrets in memory and logs: the backend zeroes buffers that held a Wi-Fi passphrase, plain or encoded (`wipe`, a volatile loop a compiler cannot drop), and every transport's debug dump of a command's data goes through `dump_out`, which hides it while `s->secret_out` is set; `saneapi.write_text` zeroes its buffer. Python strings cannot be zeroed.
- Text from the scanner (network names, model) can be any bytes: `saneapi.read_text` keeps them (surrogateescape) so they go back unchanged, and `saneapi.shown` makes them fit to show; show scanner text only through it.
- `monitor.connection_error` is the one map from a libsane status to a failure the user can fix (busy, refused), for the app and the command line.
- The config keyword is `wifi`, not SANE's usual `net`: fujitsu's networked fi-series scanners use a different protocol, so `net` would be ambiguous in this backend.
- Credentials: the SANE config is written by `sane.write_config` in a folder made with `files.private_dir` (0700, refused when it or its parent is a link or another user's), files 0600 (`files.PRIVATE_FILE`), each replaced whole by `files.replace_file`, which replaces a link instead of following it; the password is asked with `getpass` or the menu's secure field, never taken from the command line.
- The SANE config has two writers: the monitor thread (automatic setup, following the scanner, learning its MAC) and the menu (the password). `scanner.update` re-reads and writes under `scanner.CONFIGURING`, so neither loses the other's change. Automatic setup runs only when the file is absent; a damaged file is reported (`sane.configured` raises), never overwritten.
- `fujitsu.c` defines `DEBUG_NOT_STATIC` so `fujitsu-vens.c` can log; without it `DBG` there jumps to address 0.
- **Page decisions are per page** (`openscansnap/pages.py`). The blank cutoffs `NO_INK`, `INK` and `PICTURE_SHARE` rest on one real iX500 sheet (printed front, blank back with show-through) and synthetic sides (paper noise, a pencil line, a block photo); the values are in the comment above them. Between `NO_INK` and `INK` a side is kept if it has readable text that does not read better mirrored, or, when nothing reads as text, if its darker class covers at least `PICTURE_SHARE` of it. Measure more real sheets before changing these.
- On black-and-white pages, `pages.clear_edge_marks` clears only marks that touch the page edge and lie within `EDGE_BAND_MM` of it: the iX500's edge shadow (a 0.9 mm bar along the edge) and dust. Two rules failed: removing every shape that touches the band (`skimage.segmentation.clear_border`) erased table rules that run off the edge; clearing the whole band cut the top off a letterhead seal 2-3 mm from the edge (2026-11-22).
- Where data lives: settings and the SANE config (with the scanner's credentials) in `~/.config/open-scansnap/`; the log and debug mode's raw sides in `~/Library/Logs/open-scansnap/` (the app sends its stderr, Python's and the process's, to that log too: an exception in Python code AppKit calls ends the app, and its traceback is the only record of why); the latest scan, kept for review, in `~/Library/Application Support/open-scansnap/review/` (`config.REVIEW_DIR`); PDFs in the scans folder.
- The app's settings (scans folder, the two window toggles: show when paper is loaded, review after each scan; debug; scan options) are in `~/.config/open-scansnap/config.toml` over `openscansnap/defaults.toml`, the only home of their defaults (`config.default_options`); the menu writes them with `config.save`, which refuses what `config.load` would.
- A failed batch keeps its work: `sane.ScanStopped` carries the sides scanned before the failure, and the scan command saves them as the PDF. Scanned sides live in a temporary folder outside any automatic cleanup until they are in the PDF; if the PDF cannot be written, they move next to it, or stay put if that folder is the problem. A fallback must not depend on what just failed.
- Scans are taken whole (no `--swcrop`/`--swdeskew`); `sheet.straighten_and_crop` finds the sheet. SANE's `sanei_magic_findEdges` places the top from where both side edges first show, which on the iX500's light gray backing (≈234-238 against white paper) and its soft leading edge (a 1.7 mm ramp on the front sensor) lands up to 7 mm inside the paper; how much depends on which face and end go in first. ImageMagick `-trim` needs a tolerance tuned to the backing; `pschichtel/auto-crop` found no paper on the front side (2026-11-22). `sheet.py`: the backing's tones and noise come from the scan's first and last rows (the scanner always captures backing before and after a sheet); paper is brighter than every backing tone; each sample line's edge is the half-way crossing between backing and paper levels; the Theil-Sen estimator (median of pairwise slopes) fits one line per side, robust to stray points and to a wavy, curled leading edge, which a strict fit (RANSAC within 0.2 mm) rejected; the tilt comes from the left and right sides, which run along the feed; edges found again crop. A side whose samples disagree (too few find paper, or they scatter beyond `EDGE_SCATTER_MM` around the fitted line) is not an edge: it neither tilts nor crops (never cut paper). Off-white paper barely brighter than the backing scattered a letter's left edge 18 mm and turned the page 0.9 degrees wrong; a first cutoff of 2 mm, set from a few edges, refused wavy trailing edges and left backing under pages; 736 edges of 27 scans then put real edges at most 3.5 mm, failed ones at 10 mm and more (2026-11-23).
- Text straightens a side its edges cannot (owner, 2026-11-23: "use the text to align the page, not just the edges"). `sheet.straightened` reports whether the edges gave the sheet's tilt; when they did not (paper barely brighter than the backing: no side found), `job.assemble`, after show-through is removed, has `job.level_text` measure the side's text with `pages.text_tilt` (Leptonica's `pixFindSkew`, `openscansnap/leptonica.py`, ctypes; bundled with Tesseract), and `sheet.turned_level` turns the side level when the measure passes Leptonica's own cutoffs (confidence at least 3.0, tilt at least 0.1 degrees). The turn keeps all of the page (it grows a little; the corners it brings in take the paper's tone). When: the scan straightens (As scanned keeps every side whole), and `Options.level_text`, for the side's own mode, allows it (Straighten and crop in effect, not Photo). A side its edges straightened is not turned by its text: on 73 sides with text, the text then lay within about 0.1-0.3 degrees of level, and turning a cropped page moves its edges off the image border, where the edge-band rules (`clear_edge_marks`, the color strips) look for them: from about 0.5 degrees the edge shadow came back as a diagonal line. The owner may still want text askew on well-found paper turned; that needs those rules measured from the turned outline. Orders that failed (2026-11-23): measured with the backing still around the sheet, Leptonica read the backing as lines of ink (confidence 12-17, a quarter degree wrong on sparse pages); turned from the raw scan and cropped again, the crop cut paper at two corners and kept backing at the other two, and found no edge past about 4 degrees; turned before show-through, the two sides no longer lined up by a shift alone, and the back's show-through stayed. Tesseract's `--psm 2` "Deskew angle" failed too: it read a 2.8-degree tilt as 2.3 and swung 0.3 degrees on a page of six short lines. `tests/test_samples.py` requires every stored sample page to be level within 0.5 degrees.
- Binarization is Otsu's global threshold on the page as scanned or background-normalized (`pages.flatten`: paper brightness from paper pixels, interpolated under the ink at the page's own scale), chosen by Tesseract. Sauvola's local threshold turned fold creases (paper 227-247 against 254) into solid black lines; do not bring it back.
- Color: a page is color when any ink mark at least 6 pt in size has median CIELAB chroma C* >= 10 (`pages.COLORED_INK_CHROMA`), outside the 3 mm edge band (a printer's color calibration strips sit there), or Hasler's colorfulness says so (photos). Measured: black print, creases and show-through at most C* 8 on the iX500; a navy letterhead 12.5–14; blue ballpoint 20 and up. Pixel-level chroma rules failed: paper tint along creases and the colored ink itself kept contaminating the reference (2026-11-22).
- Show-through (`showthrough.clean`, rule in its docstring) runs per sheet in `job.assemble`, after both sides are cropped: the back is the front mirrored left to right (offset 3-10 px on the iX500), aligned by phase correlation. Rules that failed on real sheets (2026-11-22): a darkness cut from the sheet's measured pass-through, and a fixed spread around the other side's ink (leftover specks reached 2-3 px past it, and the spread varied 3-10 px per side). What separates copies from real marks is the share on the other side's ink: copies 73-100%, real marks crossing it at most 41%. "Lighter than the other side" keeps a side's own print when the other side shows only that print coming through (letter, 2026-11-22). A copy touching this side's print joins it into one mark through the soft edges; judged as a whole, the mark went, letters and all (a pen scribble behind a typed page erased a t and an i, 2026-11-23). Now print in such a mark starts where no copy can be: darker than `COPY_DARKNESS` of the other side's darkest ink, and darker than the other side's ink within an ink edge of the point (paper only takes darkness away; soaked marker measured at most 1.05 of its original), in spots at least a printed period's size (`PERIOD_MM`); it reaches on through what is darker than a copy could be there, kept with `PRINT_EDGE_MM` of edge. Simpler rules failed on the two samples: any pixel darker than half its original kept soaked marker cores as blobs (`drawing-and-blue-checklist` lost 8 words); print only off the other side's ink lost a t lying along a scribble line (`samples/drawing-over-text-1`, whose `expected.toml` lists words that must read: `reads`). Sides arrive front, back, front, back (`SIDES_PER_SHEET`).
- Review (owner, 2026-11-23): after each scan's PDF, a window lists every side (the blank ones left out included) with how it is stored; "Store as" (Automatic, Black and white, Gray, Color, Photo, Leave out; and As scanned for a scan made so) applies to every selected side, and Update PDF makes the PDF again in place. A side not in the PDF shows "Not in the PDF"; any mode chosen for it, the scan's own included, brings it back. It opens after each scan while `window.review_after_scan` is on; its own checkbox and the menu's "Show review after each scan" both set that one setting (owner, 2026-11-23); the menu's Review last scan… opens it any time. `review.Store` keeps the latest scan, and any the window holds, under `config.REVIEW_DIR` (`files.private_dir`): the scanner's sides as lossless PNG (6.6 MB per side; JPEG would be 5 times smaller but could flip Automatic's decisions on a remake), the pages as stored, thumbnails and `scan.json`. Storing a scan prunes the other scans; a scan whose PDF was deleted goes too (a PDF whose folder is out of reach counts as there); a scan whose record cannot be read is never pruned, since a later version may read it (`options_of` reads records tolerantly). The app prunes at start, and starts even when that fails. prune removes only the store's own folders, never through a link, and the hidden new files an interrupted `files.replace_with` left beside a scan's PDF (`files.leftovers`); what it cannot remove it logs and leaves. `hold` and `prune` take one lock, so `prune` never removes a scan that `hold` is opening for review. Picking the scan's own mode for a side clears its choice, unless the side is in or out of the PDF only because of a choice (left out, or brought back): then the scan's mode is recorded as its own choice. A choice changes how a page is stored; cropping, show-through and the sheet's turn follow the scan's settings. A side's own choice goes to `job.assemble` (`choices`); a side given a mode is kept though blank. Remakes run on the PDF thread (`Monitor.queue_pdf`, which returns a Future); a remake stages the new pages and record, then replaces the PDF in one step (`files.replace_with`, which keeps its permissions, and its Finder tags where the volume takes them), and refuses a PDF that was moved or deleted. Failing to keep a scan for review never fails its PDF. A changed side shows in the preview as its choice would store it (owner, 2026-11-23): `Store.preview` makes that one side from its sheet's raw sides, as a remake would, on the window's own preview thread with a spinner over the page, and keeps it in the scan's `previews/` folder for the next look. The list's rows are separated by lines and shading; each row's first line is how the page is stored, its last line, small and gray, its page number. When the window closes it empties the list with the scan (`let_go`): AppKit may draw the list once more, and a row of a scan let go raised there and ended the app (2026-11-23). Closed means closed by the user (`closed`, set in `windowWillClose_`), not out of sight: a minimized window is open. While an update runs, the window keeps its scan; a new scan's review waits for the menu.
- Color and gray pages are whitened (`pages.whitened`, with Clean up creases and shadows): the paper's brightness and tint divided out per channel, its grain lifted to white, colored marks kept out of the paper estimate. Whitening runs only when paper is at least `PAPER_MAJORITY` of the page, a cutoff measured on six pages, not derived; the owner accepted it on the condition that an edge case leaves the page as scanned (2026-11-23). A value too high leaves a document page as scanned; one too low turns a picture's lightest parts white.
- A side with colored ink is never blank: show-through, creases and paper measure at most C* 8 (`COLORED_INK_CHROMA` is 10), and a lone pen drawing on a back covered 0.3% of it, far under `PICTURE_SHARE` (2026-11-23).
- Installing a build on the owner's Mac: quit the app with `osascript -e 'tell application "Open ScanSnap" to quit'` and wait until it exits by itself, however long its PDFs take; never kill it. Killing it mid-PDF lost a scan (2026-11-23).
- Tests must never read or write the owner's settings: `test_config` points `config.PATH` elsewhere (which works because `load` and `save` read it when called); the menu and CLI tests replace `config.load` and `config.save` with their own. A test that read the owner's settings with Debug mode on put test scans in the owner's raw folder (2026-11-23).
- Debug mode (menu, `debug` setting) keeps every scan's raw sides in `~/Library/Logs/open-scansnap/raw/<scan>/` and logs at DEBUG. Use those raws to reproduce a bad scan offline; that is how the crop, crease and color fixes were found.
- Scanning and PDF making are separate: `job.scan` (scanner) and `job.finish` (PDF); the monitor's second thread makes PDFs so the scanner is free at once. Quit waits for PDFs in progress.
- Updates: Sparkle 2 (MIT). `updates.updater()` loads `Sparkle.framework` from the app bundle; the feed is the newest GitHub release's `appcast.xml` (`SUFeedURL`); `scripts/build-macos.sh` writes it with Sparkle's `generate_appcast`, signing with the Keychain key of account `open-scansnap` (public key `SUPublicEDKey` in the spec). Publish `dist/OpenScanSnap-<version>.dmg` (its `.sha256` too) and `dist/appcast.xml` as assets of GitHub release `v<version>`, then set `version` and `sha256` in `Casks/open-scansnap.rb` of the owner's tap, github.com/thomergil/homebrew-tap (`brew install --cask thomergil/tap/open-scansnap`; `auto_updates`, so Homebrew leaves updates to Sparkle). A release image must be notarized (`RELEASE=1`, docs/DEVELOPMENT.md); v0.1.0 was published 2026-11-23. The private key exists only in the owner's login Keychain (and their password manager): losing it means no update can reach installed copies.
- The disk image layout (owner, 2026-11-23): the app on the left, an arrow, the Applications folder on the right, the app's name above. dmgbuild (MIT, pinned in `packaging/macos/dmg-requirements.txt`, its own environment) writes it from `dmg_settings.py`; `dmg_background.py` draws the background at 1x and 2x into one TIFF; `dmg-tools/sync` answers dmgbuild's GNU-style `sync`; `check_dmg_layout.py` checks the mounted image before it is signed.
- Only `pages.upright()` rotates pages; OCRmyPDF does not rotate.
- Text language "auto" (the default, owner 2026-11-23): `job.language_of` gives each side its language before it is turned upright and read; the PDF's text layer gets every language found. `languages.detect`: Tesseract's OSD names the script; a script of one bundled language settles it, else the page is read (Latin: in English, enough to tell) and py3langid (BSD) picks among that script's languages. Read together, as the identifier cannot tell them apart: simplified and traditional Chinese, Indonesian and Malay. The language setting holds `options.AUTOMATIC_LANGUAGE` ("auto") alone, never joined with other languages; `pages.prepare` refuses it: it needs the side's language. `pages.Detection` runs Tesseract's OSD once per side, for both the language and the turn. `tests/test_languages_all.py` draws Article 1 of the Universal Declaration of Human Rights in every bundled language and requires each to be detected as itself (it needs the build's language cache).

## Dead ends (do not retry)

- SANE's standard scan commands over Wi-Fi: rejected by the firmware (see above).
- Hand-tuned thresholds or a fixed edge band from one sheet: the owner rejected them.
- SANE `--swskip`: an absolute darkness percentage, so paper tone decides blankness.
- Otsu's effectiveness measure η alone for blank detection: a uniform tone spread scores exactly 0.75, and grey backing in frame looks like ink.
- Tesseract confidence 14 (OCRmyPDF's default) as a fixed orientation cutoff: sparse pages fall below it; comparing reading before and after the turn works.
- unpaper (through OCRmyPDF or alone): leaves the edge-shadow bar; its mask scan shifts content.
- ImageMagick `-trim`: fails on the noisy backing.
- ScanTailor Advanced: no command line, no Homebrew formula. NAPS2's command line: no blank-page option.
- Python VENS client (upstream bramheerink/scansnap, removed): superseded by the SANE transport.

## Later: menu bar app and scan button

Follow the owner's `~/src/cannonball` pattern (`cannonball/menubar.py`, `status.py`, `localnet.py`, `services.py`, `packaging/macos/`, `.architecture/history/2026-11-20-macos-local-network.md`): plain PyObjC pinned by hash (not `rumps`); one `LSUIElement` app with the worker on a thread, no launchd agent (macOS denied an agent Local Network access without a prompt); a frozen status snapshot, replaced whole under a lock; a minimal menu; trigger the Local Network prompt with a UDP connect; `SMAppService.mainAppService` for login; `NSLocalNetworkUsageDescription` and `en.lproj/InfoPlist.strings` in the bundle. Testing from Terminal proves nothing about Local Network access: macOS grants it to Terminal, not to the program Terminal starts.

Scan button (verified 2026-11-22): SANE's `scan` hardware sensor (GET HARDWARE STATUS) works over Wi-Fi. A press of any length shows as `scan = 1` for one reading at 0.2 s polling, so react to its 0 → 1 edge. `page-loaded` goes 0 → 1 when a sheet is put in the feeder. ScanSnap Home's push route (trigger port 55265, `SsSvcPCWIFISCTriggerController`) is not needed. Read the sensors in-process through a `ctypes` binding to `sane-prefix`'s libsane (as the 2026-11-22 probe did): `python-sane` is published only as a source distribution, and this project installs wheels only. Close the handle before `scanimage` scans: both reserve the scanner.

Owner's choices for the app: menu bar icon is a Futura Bold "S" drawn as a template image (different from ScanSnap's slanted S), with a Wi-Fi mark or a USB plug (as large as the letter) for how the scanner is connected, dimmed while it is off, shimmering while it scans or PDFs are made (`menubar.working`, owner 2026-11-23); no window pops up when the scanner opens. Menu items are in sentence case ("Show window when paper is loaded", "this Mac"), not title case (owner, 2026-11-22). The menu, in groups: the status line (no "Last scan" line; while PDFs are made, "Processing 3/13… Ready to scan again."), the scanner's model and firmware (⚠ when newer firmware exists; opens PFU's downloads), and on USB its Wi-Fi network; Scan, "Review last scan…" (off from the moment a scan begins until its PDF is saved: owner, 2026-11-23), "Scanner password…" (when refused), "Set up Wi-Fi…" (on USB); the scans folder; Scan mode, Quality, Processing; Show window when paper is loaded, Show review after each scan, Debug mode; About (macOS's own About window: icon, version, a link to the project; owner, 2026-11-23), Check for updates, Quit. The app uses the scanner on USB when it is plugged in, else over Wi-Fi (`monitor.Connector`; the backend opens `fujitsu:usb` without reaching for Wi-Fi scanners). The window is a non-activating floating panel with a large Scan button and the scanner state.

Owner's choices for the scan settings (2026-11-22): the most capable result by default, every step switchable. No master "post-processing off" switch: As scanned is that, and one mode menu leaves no contradictory combination. Quality names rise plainly: Draft, Standard, High (not ScanSnap's names, whose "Best" sat below "Excellent").
